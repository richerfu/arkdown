## SPEC-017: Router Map Plugin

**Crate**: `arkdown-plugin-router-map`
**Priority**: P1
**Blocked by**: SPEC-005

Implements cache invalidation when the router map changes. The router map is a JSON file
listing named routes and their source files, enabling type-safe navigation in ArkTS.

### Behavior

The `should_invalidate_cache` hook returns `true` when any of the following change:

- The set of source files referenced in the router map
- The route names or `buildFunction` values in the router map

In arkdown, this is simplified: include the router map JSON content in the module graph
cache key. If the router map changes, all modules that reference it are invalidated.

The actual router map JSON is generated by `arkdown-profile` (SPEC-010). This plugin only
ensures cache invalidation is triggered when that JSON changes.

### Implementation

```rust
pub struct RouterMapPlugin {
    router_map_hash: Arc<Mutex<Option<u64>>>,
}

impl ArkdownPlugin for RouterMapPlugin {
    fn should_invalidate_cache(&self, ctx: &CacheContext, cached: &CachedModule) -> bool {
        let current_hash = ctx.build_context.router_map_hash;
        let stored_hash = self.router_map_hash.lock().unwrap();
        *stored_hash != Some(current_hash)
    }
}
```

## SPEC-018: Case-Sensitive Check Plugin

**Crate**: `arkdown-plugin-sensitive-check`
**Priority**: P1
**Blocked by**: SPEC-005

Validates that import specifiers match the actual filesystem case. Prevents CI failures
on case-sensitive Linux devices when development is done on case-insensitive macOS/Windows.

Only active when `config.product.build_option.strict_mode.case_sensitive_check == true`.

### Implementation

```rust
pub struct SensitiveCheckPlugin {
    enabled: bool,
}

impl ArkdownPlugin for SensitiveCheckPlugin {
    async fn resolve_id(&self, ctx: &ResolveContext, specifier: &str, importer: Option<&str>)
        -> PluginResult<Option<ResolvedId>>
    {
        if !self.enabled { return Ok(None); }
        // Defer to next plugin for resolution, then verify case
        Ok(None)  // pass-through; case check happens in load hook
    }

    async fn load(&self, ctx: &LoadContext, id: &str) -> PluginResult<Option<ModuleSource>> {
        if !self.enabled { return Ok(None); }
        let path = Path::new(id);
        if let Some(parent) = path.parent() {
            if let Some(actual_name) = find_actual_filename(parent, path.file_name().unwrap())? {
                let expected = path.file_name().unwrap().to_string_lossy();
                if actual_name != expected.as_ref() {
                    return Err(ArkdownError::CaseMismatch {
                        specifier: id.to_string(),
                        expected: expected.into_owned(),
                        actual: actual_name,
                    });
                }
            }
        }
        Ok(None)
    }
}
```

### Note

This plugin is a no-op on Linux (case-sensitive FS) — skip the check on Linux to avoid the
overhead of a `read_dir` call on every module load.

## SPEC-019: Incremental Build Cache

**Crate**: `arkdown-cache`
**Priority**: P1
**Blocked by**: SPEC-005

Persistent on-disk cache for incremental builds. Stores per-module snapshots so that
unchanged modules skip re-parsing, re-transforming, and re-bundling.

### Cache Key Derivation

```rust
pub struct CacheKey {
    /// SHA-256 of the source file content
    pub content_hash: [u8; 32],
    /// Config hash: SDK version + build mode + use_normalized_ohm_url + obfuscation settings
    pub config_hash: u64,
    /// Dependency hashes: hash of all direct import specifiers' resolved IDs
    pub dependency_hash: u64,
}
```

A module's cache entry is valid if and only if all three hash components match. Any change
(source, config, or dependency resolution) invalidates the entry.

### Cache Entry Contents

```rust
pub struct CachedModule {
    pub id: String,
    pub key: CacheKey,
    pub transformed_code: String,
    pub source_map: Option<String>,
    pub imports: Vec<SerializedImportEdge>,
    pub exports: Vec<SerializedExportBinding>,
    pub meta: ModuleMeta,
}
```

### Storage

Store cache entries in `build/default/.arkdown_cache/` as msgpack files. Each module gets
its own file: `<sha256_of_id>.cache`.

### Integration

`PluginDriver` in SPEC-004 checks the cache before loading/transforming:

```rust
if let Some(cached) = cache.get(&id) {
    if plugins.iter().all(|p| !p.should_invalidate_cache(ctx, &cached)) {
        return Ok(Module::from_cached(cached));
    }
}
// ... full load/transform pipeline
```

### Acceptance Criteria

- Second build of unchanged `MyApplication` completes in < 200ms
- Modifying one source file only re-processes that file and its dependents
- Config change (e.g., `useNormalizedOHMUrl` toggle) invalidates all cached entries

### BundleCache (bundle-level output cache) — implemented 2026-05-29

A coarser, bundle-level cache that skips the entire rolldown bundling step when
all compile-entry source files and the build configuration are unchanged.

**Types** (in `arkdown-cache`):
- `BundleCacheKey { source_hash: u64, config_hash: u64 }` — FNV-1a hash of all
  compile-entry source file contents (`source_hash`) and a hash of build mode +
  bundle name + API version + `useNormalizedOHMUrl` + `supportChunks`
  (`config_hash`).
- `BundledChunkMeta { name, path, is_entry, source_map }` — one chunk written
  to disk.
- `BundleCacheManifest { key, chunks }` — persisted to
  `<module>/build/default/cache/bundle/bundle.json`.
- `BundleCache { cache_dir }` — `is_valid(key)` checks key equality AND that
  all chunk `.js` files still exist; `save` / `load` for round-trips.

**CLI wiring** (in `arkdown-cli::cmd::build`):
- `compute_bundle_source_hash` — hashes all compile-entry file contents via
  `arkdown_cache::fnv1a_hash_bytes`.
- `compute_bundle_config_hash` — hashes the build-mode byte, bundle name,
  api_version, `use_normalized_ohm_url`, `support_chunks`.
- `build_bundle_cache_manifest` — builds manifest from a live `BundleOutput`.
- `bundle_output_from_manifest` — reconstructs `BundleOutput` (reads chunk
  `.js` code back from disk) so the ABC and packaging steps receive the same
  interface whether or not the cache was hit.
- Cache check runs **before** stale `.js` cleanup; a cache hit skips cleanup
  and bundling entirely via `continue` in the module loop.

## Rolldown Alignment

### SPEC-017: Router Map Plugin

| arkdown concept                            | rolldown equivalent                        | note                                                                                            |
| ------------------------------------------ | ------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| `RouterMapPlugin::should_invalidate_cache` | `Plugin::shouldInvalidCache` (rollup hook) | Direct port; same semantics: return `true` to force re-compilation of a cached module           |
| `router_map_hash` comparison               | rolldown cache key mechanism               | rolldown uses content hashing for cache keys; arkdown uses a separate hash for router map state |

**Key divergence:** rolldown does not have a router map concept. This plugin is OHOS-specific. In arkdown the router map hash is incorporated into `CacheKey::config_hash` as a simpler alternative.

### SPEC-018: Case-Sensitive Check Plugin

| arkdown concept                           | rolldown equivalent    | note                                                                                                          |
| ----------------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------- |
| `SensitiveCheckPlugin::load` (case check) | no rolldown equivalent | rolldown does not perform case-sensitivity validation; this is OHOS-specific for cross-platform compatibility |
| `find_actual_filename()` via `read_dir`   | no equivalent          | Filesystem-level check; only meaningful on case-insensitive FSes (macOS, Windows)                             |

**Key divergence:** Standard bundlers (including rolldown) rely on the OS to reject mismatched-case imports. This plugin adds an explicit cross-platform check.

### SPEC-019: Incremental Build Cache

| arkdown concept                                           | rolldown equivalent              | note                                                                                                                       |
| --------------------------------------------------------- | -------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `CacheKey { content_hash, config_hash, dependency_hash }` | rolldown module cache key        | rolldown uses content hash only; arkdown adds `config_hash` and `dependency_hash` for OHOS-specific invalidation           |
| `CachedModule`                                            | rolldown cached `NormalModule`   | rolldown stores AST + resolved imports; arkdown stores transformed code + serialized import/export edges (no AST in cache) |
| `should_invalidate_cache` hook                            | rollup `shouldInvalidCache` hook | Identical concept; both are sync boolean functions                                                                         |
| msgpack cache files in `build/.arkdown_cache/`            | rolldown in-memory cache         | rolldown keeps its cache in memory only; arkdown persists to disk for cross-process incremental builds                     |

## Test Requirements

### SPEC-017

- `should_invalidate_cache` returns `true` when `ctx.build_context.router_map_hash` differs from the stored hash
- `should_invalidate_cache` returns `false` when hashes match
- First build (no stored hash): `should_invalidate_cache` returns `true` for all modules
- Plugin name returns `"router-map"`

### SPEC-018

- Case mismatch `"./Utils/Helper"` for actual file `"./utils/helper"` → `Err(ArkdownError::CaseMismatch)` when `enabled = true`
- Correct case `"./utils/helper"` → `Ok(None)` (pass-through to next plugin)
- `enabled = false`: all specifiers pass through as `Ok(None)` without any filesystem check
- On Linux: `enabled = true` but the `read_dir` check is skipped (no error possible from case mismatch on case-sensitive FS)
- Plugin name returns `"sensitive-check"`

### SPEC-019

- A module loaded twice with the same source content hits the cache on the second call (no re-parse, no re-transform)
- Changing the source content invalidates the cache entry
- Changing `config_hash` (e.g., `useNormalizedOHMUrl` toggle) invalidates all cached entries
- Changing the resolved ID of one of a module's imports invalidates that module's cache entry (`dependency_hash` change)
- Cached module round-trip: `CachedModule` serialized to msgpack and deserialized produces identical `transformed_code`, `imports`, and `exports`
- Cache directory created at `build/default/.arkdown_cache/` if absent
- `should_invalidate_cache` returning `true` from any plugin causes cache bypass for that module
- `should_invalidate_cache` returning `false` from all plugins uses the cached module (load + transform hooks not called)
